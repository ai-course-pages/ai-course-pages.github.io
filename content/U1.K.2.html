A few skills, and the ones already there

Before you add a skill, see whether the product already has one for that job. U1.K.1 is how a skill is packed. This page is about whose skill you load, and how many.

If these words are new

A learner with little background would want U1.K.1 first, for what SKILL.md is. This page uses that, and the habit of not sending more text than the turn needs.

Already inside, or brought in

U1.K.1 is where a skill is packed, and where you look when the product wrote one and the place is easy to miss: a screen in the product, a question in the chat, or a folder the product names. This page starts once you can see that skill. The question here is whether another file would cover the same job.

An internal skill ships with the product, or the product writes it as you work. A CLI or a desktop app is where that set is often already installed. The product may write a further skill when you ask, when a setting allows it, or on its own when it judges a procedure worth keeping. Those habits differ by product and by settings. Look for what is already loaded before you add a file.

An external skill was written outside that product. It may be aimed at one model, at a few, or at anyone who can read a SKILL.md. Popular families are moving toward that shared shape. They have not all adopted a single standard. A skill from another family can still be worth ingesting when the procedure is plain and it says when it applies.

Two skills for one job

An external skill laid on top of an internal skill that covers the same work is a dual setup. The model can read both, spend tokens on both, and follow whichever instruction it meets. When the two files disagree, the reply follows the mix. For a job one skill already covers, keep that one.

Later models are likely to get better at absorbing an older skill, and at reconciling an internal skill with an external one. That is a direction. The model you are using today may still follow both.

How many to bring in

A few external skills that match work you actually repeat are enough. A large hunt is a weak way to get better results. A skill from a somewhat older model often still works.

Families also change quickly. A portable skill, written so another family can follow it, with a clear trigger and short standing rules, can be a better import than an old skill from your own family that assumes an earlier product's habits.

Suggested exercise

Before you add a file, paste this in the session that would receive it.

Before I add an external skill, list the skills already available in this session that touch the same job.
For each one, say in one line what it covers.
If one was written by this product, say how I can open it: a screen in the product, your answer in this chat, or a folder you name.
Then say whether the new skill would duplicate one of them, or cover a job none of them cover.
If it would duplicate one, say which one to keep.
