How to pace one usage window

A usage window is one clock with an amount and a reset time. Two common plans use the same arithmetic. Spend-down means the leftover expires at the reset, so the useful work should happen before then. Even pace means spreading the window across its days, then repairing the later days when one day runs hot or cold.

Where the number shows up

In a web app, the meter is usually under settings, subscription, or a usage page. In a coding CLI, it is often a slash command. In Grok Build that command is /usage. Inside a session it shows the account allowance and this session's context and token totals. /usage manage opens billing. From a shell, grok usage plus a session id shows per-turn totals for a saved session.

Many products also speak up on their own, at a few percentages and again when you hit a cap. That hint names a clock. The settings page or /usage is where you see the rest of the clocks.

The repair rule

After any day, the target for what is left is the remaining percent divided by the days left in the window, counting today if today is not finished.

A weekly even pace starts near one seventh, about 14% a day. If the first day uses 20%, 80% is left for six days, about 13% a day. If the first day uses 8%, 92% is left for six days, about 15% a day. A light day gives the later days room. A heavy day borrows from them.

Spend-down is the same rule on the last stretch of the window. The days left shrink toward one, so the target becomes "what is left, before the reset."

A spend-down window

One real window: 32% of a weekly SuperGrok allowance is used, so 68% is left. The reset is 26 September 2026 at 11:51 AM. The plan is to put that 68% into useful work before the reset, rather than save it. Saving it past 11:51 AM throws it away.

The session that does this work is already long, and its effort is high. Each further high turn sends the whole thread again and then does a lot of hidden reasoning. The 68% will cover fewer turns than the same 68% in a new short chat. That is acceptable while the turns need the thread. It is waste when the turn is only a confirmation.

The next turnSet
A new piece that has to fit several earlier decisions high
Revise one page whose outline is already agreed medium
Report a meter reading, confirm a choice, or change a few words low
Extra High Not in this window. A spend-down is not a reason to try it.

A shorter clock can still pause you at 50% of the weekly meter. If that pause ends before the weekly reset, continue. If it would outlast the reset, the weekly leftover expires during the pause.

Suggested exercise

Run /usage and note the weekly percent. Set the next turn with the table above. Run /usage again. The gap is what that effort cost on a thread of this length. Copy the prompt if you want another model to classify the two readings.

Weekly allowance reading 1: [percent and reset time]
Weekly allowance reading 2, after one turn: [percent]
The turn's effort was: [low, medium, or high]
The chat was: [new, or already long]

Say how many percentage points that turn used. Say whether the next turn of the same kind should stay at that effort or drop one step.
