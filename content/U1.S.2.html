Export a web thread into a seed

A web chat has no project folder until you make one. Leaving it works like ending a coding session: the next thread should receive a small seed, not the whole transcript. The seed can be a prompt, a saved file, or both. The page before this one, U1.S.1, is the coding-CLI version of the same handoff.

If these words are new

A learner with little background would want U1.B.1 first. A follow-up resends earlier turns. A new chat does not, unless you put the needed facts in the first message.

Which thread to practice on

Use a thread you are willing to stop using. Two ways to get one:

  • Build a short disposable thread with the three prompts below. It exists only for the export.
  • Or pick an existing thread that was useful, and that you do not need to keep open.

Do not practice this on the only copy of a job you still have to finish inside that same chat.

We are setting up a disposable practice thread. In one paragraph, state this decision: a weekly allowance can be paced at about one seventh per day.
Add one constraint: a one-line check in a long thread does not need high effort.
Add one handoff rule: when a section of several segments holds together, the next chat should start from a short seed, not from the whole transcript.

The export prompt

Paste this at the end of the thread you are leaving. It asks for a seeding prompt, a reference file, or both. A model that cannot create a downloadable file can still answer with the prompt alone. That is a complete result.

This thread is about to be left. A new thread may continue the work.

Produce the smallest seed that keeps the decisions and the open task. Leave out dead ends.

You may do either or both:
1. Write a seeding prompt I can paste as the first message of the new thread.
2. Write one or more reference notes I can save and attach. Name each note.

Do not assume the next product can create files. Do not assume it will treat an attachment as the prompt.

How to open the new thread

If you only received a seeding prompt, paste it into the new thread as the first message.

If you also have a file, attach it and still type a line in the prompt box. A reliable line is See: decisions.md, using the real file name. Several files get one line that names each of them, such as See: decisions.md and open-task.md.

  • Some products can read an attached file as the whole request. The See: line is still worth typing, so the request is unambiguous.
  • Some products refuse an attachment when the prompt box is empty. One short line is enough.
  • Some products answer "what do you want me to do with this file?" when the box is empty, even if the file itself contains a prompt.

The coding-CLI practice of this handoff waits until you want a new session. Use the template on U1.S.1 as the first message. This web export can be practiced earlier, on a disposable thread. A thread you are staying in, where the product may compress or compact on its own, is the next page, U1.S.3.
