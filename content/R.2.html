Three piles of data

Data is the material a result is drawn from. While this course is being written, three piles count, and mixing them makes the result harder to check.

  1. What a person points at. In a prompt, that is the files and the passages they name. Choosing those is human data selection.
  2. What the course already holds. The lessons, the tables, and the plans are data too. They are read directly.
  3. What the assistant opens next. That selection follows the person's instructions, the program's rules, and the settings in use. It is a second selection.

An outside source joins the third pile when the person asks for it. A page that can name its three piles is easier to reopen later and widen.

One decision tree

An algorithm here is a procedure that can be followed the same way each time. This one decides what to do with a course piece. Ask it once per piece. A list of many rows, and the paragraph that explains them, are two pieces.

The same steps in a form a person can follow by hand:

if the idea is not easy to say in one or two sentences:
    leave a stub
else if many items share one frame:
    keep the items in a table and draw the listing from the table
    if a second lesson would copy the same frame:
        generate those lesson bodies from the table
    else:
        write the lesson body as one static page
else:
    write one static page

A short program answers the first two questions. It is the same procedure, small enough to check by hand. The inner step, generating lesson bodies, stays in the prose until a second lesson would copy a frame.

def choose(easy_to_say, many_share_a_frame):
    if not easy_to_say:
        return "stub"
    if many_share_a_frame:
        return "table"
    return "static"

This page is the static result. The idea fits in a few sentences, and the page is the first of its kind. Five steps, used on this page

Building a page with an assistant is one case of problem solving. The steps are ordinary. They are the ones that produced this page, in a coding session with Grok.

  1. Say the problem in one sentence.
  2. Name the three piles of data.
  3. Pick a procedure you can say aloud.
  4. Leave a result the next session can open.
  5. Leave a stub where a wider scope will go.

The sentence for this page was: choose the data and the page form so a newcomer can repeat the idea. The wider scope is the waiting list.
