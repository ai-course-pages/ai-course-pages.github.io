File types

A file type is a convention for what a file holds and how to read it. You often see it as the ending of the name: .md, .json, .yaml. The ending is a hint. The contents still have to match what that type expects.

The wording for each type lives in the glossary. That list is expected to grow. This page is the short introduction, so the endings in the using-models section have one place to meet.

Plain text, and three formats on top of it

Plain text is text you can read in an editor without a special program. A file ending in .txt is plain text with no further rules. Markdown, JSON, and YAML are plain text plus a few rules.

  • Markdown (.md) is how these lessons are written, and how SKILL.md is written. Headings, lists, and code use a small set of marks.
  • JSON (.json) is for structured data a program can read without guessing. Names and text sit in double quotes.
  • YAML (.yaml or .yml) is for a small structured block. Indentation shows what belongs under what. A field is a name, a colon, and a value. A skill bundle often uses it for frontmatter. It is looser than JSON.

A pack of files, and a stub

A zip file packs other files into one, including folders. A skill bundle may arrive that way.

Python (.py) is a programming language. Helper scripts beside a skill are often Python files. The glossary entry is a stub: enough to recognize the ending, with a fuller account later.
