One message, or the same thread

A token budget is the amount of text a product will count before it pauses you or charges you. Two habits spend that budget in different ways: sending one request on its own, and continuing in a thread.

If these words are new

This page sits after the effort page. A learner with little background would want these earlier ideas. They can stay unwritten. You can keep going.

  • U0.1 A model reads a prompt and writes a reply.
  • U0.2 Input, hidden reasoning, and the reply are counted apart.
  • U1.E.1 Effort allows more or less hidden reasoning. It does not change which model answers.

A one-off request

A one-off request is a new chat. The input is that message, plus whatever instructions the product always attaches. The reply, and any hidden reasoning, are counted once. The next topic can be a new chat too. The old reply is not sent again.

Continuing a thread

A thread is the same chat. Each new message is counted together with the earlier turns the product still keeps. That includes your messages, the model's replies, and, in a coding session, a lot of tool output. The input pile grows as the thread grows. The same short question costs more on turn twenty than it would have in a fresh chat.

Some products shorten or summarize older turns. The thread can still cost more than a new chat, and a summary can drop a detail you still needed. When a later answer ignores an early instruction, check whether that instruction is still in the thread before you raise effort.

Which habit fits

  • Continue when the next step uses the last answer, a file already in the chat, or a decision you just made.
  • Start a new chat when the question stands alone, the topic has changed, or the thread is long and full of side paths.

Effort applies to each turn. High effort in a long thread pays for a large input and a large pile of reasoning. That is a poor place to try Extra High for the first time. Learn low, medium, and high on short chats first. The effort page is U1.E.1.

Suggested exercises to try

Copy each prompt. Send the first in a new chat. Send the second in that same chat. Send the third in a different new chat. Then say which reply actually needed the earlier turn.

  1. Define a token in one sentence.
  2. Using only that definition, say whether a long thread increases the input tokens of the next message. One sentence.
  3. Does a long thread increase the input tokens of the next message? Answer in one sentence.

The second prompt is a follow-up. The third is a one-off of the same question. Medium is enough for all three. High adds reasoning tokens the question does not need.
